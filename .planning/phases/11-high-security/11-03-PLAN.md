<objective>
Eliminate the per-request Supabase auth round-trip (audit H7) by caching JWT validation results in an in-process LRU with 60s TTL, keyed by `sha256(token)`. After this plan, two consecutive `/api/*` requests with the same Bearer token result in exactly ONE call to `supabaseAnonClient.auth.getUser`.

Purpose: Today, every authenticated request (`src/server/index.ts:185`) calls Supabase Auth API. A logged-in user browsing the dashboard fires 5-20 API calls per page view × Supabase round-trip latency (typically 50-200ms each). This is both a perf gargalo and a hard dependency on Supabase auth availability for every request. A 60s LRU cache (per Phase 11 CONTEXT decision) cuts auth API calls by 10-100x for warm users, and gracefully degrades to current behavior if cache is cold or token unknown.

Output:
1. `src/server/lib/auth-cache.ts` exporting `resolveUserFromToken(token: string): Promise<{ user: User | null; error?: AuthError; fromCache: boolean }>` with in-flight dedup and TTL.
2. `src/server/index.ts` auth middleware uses it instead of calling `supabaseAnonClient.auth.getUser` directly.
3. Dev-only log line emitted every N requests with cache hit-rate.
</objective>

    ```ts
    import { createHash } from 'node:crypto'
    import { supabaseAnonClient } from './supabase'

    // SEC-03 — see .planning/debug/system-wide-audit-2026-05-16.md H7

    const TTL_MS = 60_000        // 60s
    const MAX_ENTRIES = 5000     // CONTEXT.md decision

    type CachedUser = {
        id: string
        email: string | null
        firstName: string
        lastName: string
        emailVerified: boolean
    } | null  // null = "verified-invalid" — not cached; we only cache successes

    type Entry = {
        user: NonNullable<CachedUser>
        expiresAt: number
    }

    const cache = new Map<string, Entry>()         // key = sha256 hex
    const inflight = new Map<string, Promise<{ user: NonNullable<CachedUser> | null; error: string | null }>>()

    let hits = 0
    let misses = 0
    const isDev = process.env.NODE_ENV !== 'production'

    function hashToken(token: string): string {
        return createHash('sha256').update(token).digest('hex')
    }

    function evictExpired(now: number): void {
        // Lightweight pass — only on miss path
        for (const [k, v] of cache) {
            if (v.expiresAt <= now) cache.delete(k)
        }
    }

    function evictLRUIfFull(): void {
        if (cache.size < MAX_ENTRIES) return
        // Drop oldest insertion (Map preserves insertion order)
        const firstKey = cache.keys().next().value
        if (firstKey) cache.delete(firstKey)
    }

    export async function resolveUserFromToken(token: string): Promise<{
        user: NonNullable<CachedUser> | null
        error: string | null
        fromCache: boolean
    }> {
        const key = hashToken(token)
        const now = Date.now()

        // Cache hit
        const cached = cache.get(key)
        if (cached && cached.expiresAt > now) {
            hits++
            maybeLogStats()
            return { user: cached.user, error: null, fromCache: true }
        }

        misses++

        // In-flight dedup — share a single Supabase call for identical concurrent tokens
        const existing = inflight.get(key)
        if (existing) {
            const r = await existing
            return { user: r.user, error: r.error, fromCache: false }
        }

        const p = (async () => {
            const { data, error } = await supabaseAnonClient.auth.getUser(token)
            if (error || !data?.user) {
                return { user: null, error: error?.message ?? 'Invalid or expired token' }
            }
            const u = data.user
            const compact = {
                id: u.id,
                email: u.email ?? null,
                firstName: (u.user_metadata?.firstName as string | undefined) ?? '',
                lastName: (u.user_metadata?.lastName as string | undefined) ?? '',
                emailVerified: Boolean(u.email_confirmed_at || (u as any).confirmed_at),
            }
            // Cache successes only — never cache 401s (token could be rotated / revoked rapidly)
            evictExpired(now)
            evictLRUIfFull()
            cache.set(key, { user: compact, expiresAt: now + TTL_MS })
            return { user: compact, error: null }
        })()

        inflight.set(key, p)
        try {
            const r = await p
            maybeLogStats()
            return { ...r, fromCache: false }
        } finally {
            inflight.delete(key)
        }
    }

    function maybeLogStats(): void {
        if (!isDev) return
        const total = hits + misses
        if (total > 0 && total % 100 === 0) {
            const hitRate = ((hits / total) * 100).toFixed(1)
            console.log(`[auth-cache] ${total} lookups, hit-rate=${hitRate}% (hits=${hits} misses=${misses}, size=${cache.size})`)
        }
    }

    export function getAuthCacheStats(): { hits: number; misses: number; size: number; ttlMs: number } {
        return { hits, misses, size: cache.size, ttlMs: TTL_MS }
    }
    ```

    **Notes:**
    - `supabaseAnonClient` is imported from `./supabase` (per existing pattern at `src/server/index.ts:185` which imports it; verify the relative path by grepping `from.*supabase` in src/server — adjust import if path differs).
    - Map iteration insertion-order property is standardized (ES2015+), so first-key eviction is true LRU-by-insertion (acceptable approximation; "true" LRU-by-access would require touching insertion on hit — skipped for simplicity since TTL is short).
    - Failed lookups (`error || !user`) are NOT cached — preserves current security semantics (revoked/rotated tokens are not served from cache).
    - In-flight dedup means a burst of N identical-token requests hits Supabase once.

<risks>
- **Stale user data within TTL window.** If admin changes user metadata in Supabase dashboard, app sees old `firstName/lastName` for up to 60s. Acceptable — these are cosmetic; auth status (id, email_verified) cached too but those don't change frequently. Logout doesn't invalidate cache (acceptable per CONTEXT decision; 60s bound).
- **Token revocation latency = 60s.** If a token is revoked via Supabase (e.g. user changes password), it remains valid in cache up to 60s. Audit accepts this tradeoff (H7 is perf-focused). If stricter semantics needed later, drop TTL to 15s.
- **Map-based LRU is approximate.** True LRU would re-insert on hit (we don't, for simplicity). With 5000-entry cap and 60s TTL, working set effectively bounded by active-user-count × tokens-per-user. Realistic max is a few hundred entries for SkaleClub's scale.
- **In-flight dedup has a subtle case:** if Supabase returns an error for one concurrent caller, ALL concurrent callers of the same token see that error. Correct behavior (token genuinely invalid for all of them).
- **Header property rename** (`x-user-first-name` now derived from cache.firstName instead of `user_metadata?.firstName`). Sanity check: grep for `x-user-first-name|x-user-last-name|x-user-email-verified` consumers — they read string headers, not the underlying source. No consumer changes required.
</risks>
