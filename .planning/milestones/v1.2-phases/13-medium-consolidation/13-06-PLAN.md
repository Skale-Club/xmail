<objective>
QUA-08 — Rename two TS property names in `src/db/schema.ts` to match the camelCase convention used everywhere else in the schema:
- `organizations.owner_id` → `organizations.ownerId` (SQL column stays `owner_id`).
- `organizations.outreach_enabled` → `organizations.outreachEnabled` (SQL column stays `outreach_enabled`).

Drizzle separates TS field name from SQL column name: `ownerId: uuid('owner_id')` means "TS calls this `ownerId`, the column is `owner_id`". The schema already follows this pattern for every other column (e.g. `firstName: text('first_name')`). The two organizations.* columns were exceptions — this plan fixes that.

Purpose: Eliminate cognitive friction. Every contributor + every grep search currently has to remember "is this column camelCase or snake_case in TS?" — and for these two, it's the wrong answer. After this plan, the rule is uniform.

Output: 5 files modified. Plan 13-01 (Wave 2) will run `tsc --noEmit` afterward to catch any straggler call sites the grep missed.
</objective>
