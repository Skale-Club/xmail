<objective>
Eliminate the audit C4 / CRIT-04 finding: the codebase's authorization story is currently misleading. `CLAUDE.md` claims "RLS policies enforce organization-level data isolation at the database layer," but the app's Postgres connection uses the `DATABASE_URL` role which bypasses RLS entirely — the JS-side `checkXAccess` helpers are the real source of truth. If a new route forgets to call one, there is no DB safety net.

Purpose: Make the auth model honest in documentation AND give developers a single, discoverable entry point (`src/server/lib/access.ts`) so adding new routes consistently calls the right helper.

Output: A consolidated `src/server/lib/access.ts` that re-exports the existing scattered `checkXAccess` functions (no mass rename in this phase — Phase 11+ can migrate call sites later), and a CLAUDE.md whose Authentication Flow and Multi-Tenancy sections describe reality.
</objective>

## Goal

`src/server/lib/access.ts` is the canonical import path for access helpers, and `CLAUDE.md` accurately describes the JS-as-source-of-truth + RLS-as-defense-in-depth auth model.

## Scope

**In scope:**
- Discover every `checkXAccess`-style helper in `src/server/**/*.ts` via grep.
- Create `src/server/lib/access.ts` that **re-exports** them (does NOT move the implementations — that would force a mass rename across all callers, which 10-CONTEXT.md explicitly defers).
- Add a top-of-file JSDoc block in `access.ts` describing usage and linking to CLAUDE.md.
- Update CLAUDE.md `## Architecture Notes > Authentication Flow` and `> Multi-Tenancy Model` sections to accurately describe:
  - DB connection uses the `DATABASE_URL` Postgres role.
  - This role bypasses RLS (no `auth.uid()` set per request).
  - RLS migrations remain as defense-in-depth.
  - Real authorization lives in JS via `checkXAccess` helpers from `src/server/lib/access.ts`.
  - **Every new API route MUST call an access helper before reading/writing data.**

**Out of scope:**
- Moving the actual implementations of `checkXAccess` functions to `access.ts` (creates mass rename — deferred per 10-CONTEXT.md and STATE.md decisions).
- Auditing every existing route for missing `checkAccess` calls (deferred to a future hardening pass).
- Persistent audit-log table for sensitive operations (deferred per 10-CONTEXT.md).
- Changing connection strategy to use a Supabase-auth-context role (explicitly out-of-scope for v1.2 per REQUIREMENTS.md "Out of Scope").
