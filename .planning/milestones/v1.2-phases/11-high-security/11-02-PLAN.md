<objective>
Eliminate the IMAP MITM vulnerability (audit H5) where `src/server/lib/mail-sync.ts:541` accepts any TLS certificate — including self-signed and expired — when syncing user mailboxes from external IMAP servers. After this plan, the default is `rejectUnauthorized: true`, and only mailboxes with the new opt-in `skipTlsVerify` flag bypass verification.

Purpose: The current code at `mail-sync.ts:70-72` already conditionally rejects in production but unconditionally accepts in dev (and the sync-test path at line 541 unconditionally accepts everywhere — see audit H5). Either path is a MITM vector: an attacker on the network between the SkaleClub server and the user's IMAP server (think: hotel WiFi for a self-hosted dev instance, or a corporate proxy MITMing TLS) can intercept IMAP credentials and mail contents. Strict TLS by default closes this. Per-mailbox opt-in preserves the legitimate use case of self-signed corporate IMAP servers.

Output:
1. New `skip_tls_verify` column on the `mailboxes` table (SQL migration + Drizzle schema field).
2. `createImapConnection` in `mail-sync.ts` uses `rejectUnauthorized: !mailbox.skipTlsVerify` (no NODE_ENV branching).
3. The second IMAP construction site at `mail-sync.ts:533-541` (used inside `testMailboxConnection`) receives the same treatment — accepts an optional `skipTlsVerify` arg, default false.
</objective>
